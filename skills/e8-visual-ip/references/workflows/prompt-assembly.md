# Prompt 组装协议

Prompt 是图片修改与重生的文字真源。每张候选使用一份完整 Prompt；修改图片前先修改 Prompt。

## 读取顺序

1. 从 `references/style-registry.json` 解析选中风格。
2. 读取该条目的 `definition`。
3. 若风格定义指定专属 Prompt Profile，再读取对应 Profile；专属 Profile 覆盖公共表达。
4. 读取当前交付类型与相似程度定义。

不要一次加载未选中的风格。

## 必须包含的九段

```text
1. 任务与画布
2. 转换策略
3. 人物身份锚点
4. 相似程度
5. 选中风格的生产规则
6. 配色策略
7. 当前交付类型
8. 参考图用途、顺序与禁止迁移项
9. 不可变项、失败条件与输出要求
```

### 任务与画布

写清单人或多视角、完整全身或头像、背景、构图和是否为正式基础人物。不要用“画得好看一点”代替可观察要求。

### 转换策略

使用注册表中的 `transformation_policy`。`structural-redraw` 必须明确从空白画布重构形状语法；`surface-mapping` 才允许锁定具体轮廓只改变媒介。

### 人物身份

`interpreted/symbolic` 写 2～5 个稳定符号锚点。`recognizable/close` 必须写入分析框架中的五项身份指纹：脸部比例、发际线额头、眼眉关系、中下脸关系和年龄神态；服装与道具不能替代脸部身份。背景、拍照姿势、影棚光和临时穿搭默认不属于身份。

### 风格规则

原样保留选中风格定义中的比例、五官、形状、线条、媒介、配色和呈现硬门；不要压缩成“可爱Q版”“黑白线稿”或“像素感”。`reference_maturity` 与未验证能力不能被 Prompt 掩盖。

### 参考图用途

Prompt 必须逐张声明：

```text
[primary identity] <实际路径>：当前人物的脸部与身份真源。
[secondary identity] <实际路径>：只补充主身份图缺失的侧脸、发际线或招牌特征。
[primary style] <实际路径>：控制比例、形状、线条、媒介与呈现。
[secondary style] <实际路径>：只补充指定局部规则。
[edit-target] <实际路径>：仅当用户明确要求局部编辑时使用。
```

同时列出不得从参考人物迁移的脸、服装、配饰、文字、道具、性别表达和配色。负面 QA 样本永远不传入生成工具。

风格定义声明 `reference_strategy` 时必须照其执行。`identity-first` 把主身份图放在第一位；`style-first` 把主风格图放在第一位。不要默认认为风格图永远优先，也不要把多张身份照片视为天然更可靠。

每次生成授权默认只对应一张当前阶段候选。Prompt 必须写明 `one candidate only`；不得在同一调用中同时要求头像和全身图，也不得预先计划未获用户授权的第二版。

## 生成前一致性门

生成前逐项核对：

- `plan.md` 已存在。
- 本候选完整 Prompt 已保存。
- Prompt 中的身份图、主风格图、辅助图与计划一致。
- 图片工具调用将真实传入同一组参考；支持多参考图的工具必须把已记录的身份图和风格图真实传入调用。
- 已声明参考图输入顺序的风格严格遵守其定义。
- 本轮只生成一张候选；额外脸部校准或第二版没有被静默加入计划。
- 注册表要求运行校验器时，`run-contract.json` 已通过 `--phase pre`。

任一项失败都不得调用图片工具。

## 工具能力降级

- 多参考工具：按风格的 `reference_strategy` 传一张主身份图＋主风格图；只有确实补充缺失信息时才加一个辅助参考。
- 单参考工具：生成已确认风格的衍生图时优先传正式风格锚点；创建新 `structural-redraw` 风格时优先传身份锚点，并明确说明风格一致性降低。
- 不支持参考图：只能使用文字定义，并把一致性限制告诉用户；不得描述为高保真还原。

工具输入、Prompt 和 `plan.md` 不一致时，以停止生成为默认处理，而不是静默删掉参考。
