# 自动选择

自动选择负责排序推荐，不替用户确认。

## 人物方向

| 用户信号 | 推荐 |
|---|---|
| 像本人、个人分身、别人能认出 | `recognizable-chibi` |
| 抽象、角色感、图形化、缩小识别 | `graphic-chibi` |
| 吉祥物、符号、不要真人脸 | `symbolic-mascot` |
| 不确定 | `recognizable-chibi` |

## 相似程度

| 用户信号 | 推荐 |
|---|---|
| 尽量像本人，但明确要Q版 | `close` |
| 能认出来、有个人气质 | `recognizable` |
| 更抽象、更像独立角色 | `interpreted` |
| 完全符号化 | `symbolic` |

## 表现风格

| 用户信号 | 推荐 |
|---|---|
| 潮玩、手账人物、生活方式Q版、软萌三视图、参考图类似内置风格1 | `soft-toy-chibi` |
| 用户只说Q版或个人分身，但没有指定具体画法 | 展示风格目录并推荐，不静默选中 |
| 用户没有提供任何风格信息 | 展示风格目录并推荐，不静默选中 |
| 纯黑白、漫画线稿成品、黑白角色设定、黑白三视图、只要黑线与白底 | `monochrome-manga-sheet` |
| 像素人物、像素三视图、暗色街头角色、有限色板、复古游戏角色 | `streetwear-pixel-sheet` |
| 用户给新的风格图 | 与三个内置风格比较形状语法和媒介差异；确实属于新风格时建立自定义候选，不冒充已有内置风格 |
| 用户要求纸感、彩铅、水彩、马克笔等当前未内置风格 | 识别为新增自定义风格任务；需要参考或完整定义并单独确认，不调用已删除旧风格 |

### 目录选择规则

- 用户没有指定风格时，自动选择只负责给三个内置风格排序并标出一个推荐，不产生已选风格。
- 用户回复风格名称、编号或“采用推荐”后才形成初始风格选择。
- 用户明确说“你帮我选”“风格你决定”时，可以代选，但必须展示被选中的正式目录预览和具体理由。
- 用户根据目录预览选中风格时，注册表中的 `catalog_primary_style` 是本次默认主风格参考；内部参考路由不得静默替换它。

### `monochrome-manga-sheet` 适用判断

- 用户明确要求纯黑白最终成品，而不是待上色线稿。
- 用户接受身份色被转译成形状、位置和黑白面积，不要求保留原色。
- 目标适合修长 Q 版、克制漫画脸和大量白色负空间。
- 长发、浅色头发、复杂配饰、复杂动作或场景属于单参考未充分覆盖范围；先生成单张候选，不批量扩展。
- 用户只说“线稿”但没有说明是否最终成品时，不自动选择；先判断是制作过程还是最终风格。
- 默认相似度使用 `interpreted`，只锁定 2～5 个身份锚点；用户明确要求更像本人时最多推荐 `recognizable`，不默认使用 `close`。
- 黑白正面首次生成必须优先使用裁切后的正面风格参考，不使用完整三视图作为主参考。

### `streetwear-pixel-sheet` 内部参考路由

- 从目录选择本风格时默认使用 `accessory-purple` 预览家族及其正面裁图。只有用户同意切换为更暗、更酷的另一套内部参考后，才使用 `hair-accent-dark`。
- 短发、耳机／帽子／大型配饰承担识别、希望有明确服装主色 → `accessory-purple` 主参考。
- 中短层次发型、挑染或发型承担识别、整体更暗更酷 → `hair-accent-dark` 主参考。
- 同时命中时选择最能保留本人剪影的一张为主；至多增加对应头部裁图，不把两张人物机械平均。
- 默认相似度 `interpreted`；用户要求更像本人时最多提升到 `recognizable`。
- 长发、浅色服装、裙装、复杂道具和场景超出当前充分覆盖范围，先生成单张正面候选。

### `soft-toy-chibi` 内部参考路由

- 从目录选择本风格时默认使用 `minimal-face` 正式预览。以下内部路由只作为替代建议，必须先向用户展示差异并获得同意，不能依据照片静默换图。
- 五官信息少、气质克制、需要极简可爱 → `minimal-face` 主参考。
- 眉眼、眼神或情绪是关键身份锚点 → `expressive-eye` 主参考。
- 眼镜、发型、职业或生活配饰承担识别 → `accessory-led` 主参考。
- 需要清楚睁眼、跨视角稳定，但不需要精细动漫虹膜 → `round-open-eye` 主参考。
- 用户同意替代路线后，选择最能保留本人身份的一张为主，至多增加一张辅助；不把四张机械平均。
- 闭眼、笑眼等眼型属于表情变量；基础人物尚无正式眼型时，不以闭眼候选代替眼型锚点。
- 选择 `minimal-face` 后必须读取其专属 Prompt Profile；不得仅使用 soft-toy 通用 Prompt。

## 配色

- 多张照片重复出现或用户明确喜欢的颜色优先。
- 环境光、背景和单次服装颜色默认不进入身份色。
- 配色过多时压缩为主色、辅助色和强调色。
- 招牌符号优先承担强调色。

## 低情境照片

- 单张证件照或朴素正装照只提供身份，不把服装、背景和姿势自动判为稳定特征。
- 有档案或当前用途时据此设计角色服装；没有背景资料时推荐角色中性方案，不推断职业或添加职业道具。
- 正装是否属于长期职业身份会实质改变角色时，先给出 Skill 的首选判断，只允许用户纠正该事实，不反问专业设计参数。

## 交付类型

直接根据用户动词选择：设计人物→`base-character`；增加风格→`style-variant`；做头像→`avatar`；做表情→`expression`；做动作→`pose`；检查是否同一个人→`consistency-audit`；修复某张图→`repair`。

## 推荐说明

向用户展示推荐时必须说明为什么适合，不使用“更高级、最好看、最专业”等空洞理由。用户不知道怎么选时可以采用推荐；用户明确选择时优先执行用户选择并提示明显兼容风险。
