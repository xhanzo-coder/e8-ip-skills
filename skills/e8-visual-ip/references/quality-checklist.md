# 三层质量检查

所有候选都必须与主风格参考并排查看。先判断硬门，再谈审美；“漂亮”“像本人”或“属于宽泛Q版”不能覆盖风格失败。

## 1. 人物身份层

- 2～5 个稳定身份锚点是否仍可识别。
- 脸龄、气质、发型剪影、正式眼型和长期配饰是否连续。
- 是否误把照片姿势、背景、影棚光或临时穿搭固化为身份。
- 是否复制了风格参考人物的脸、服装、配饰、道具或性别表达。

当相似程度为 `recognizable` 或 `close` 时，必须额外逐项检查：脸部宽高与下颌、发际线与额头、眼眉关系、鼻口下巴关系、年龄与稳定神态。发型、眼镜、服装或道具成立，只能算辅助证据；若遮住这些类别符号后脸部仍是通用人物，身份层必须为 `FAIL`。

风格定义声明专属 `identity_anchors` 时，`qa.md` 必须逐项记录其标识和可见证据。不能使用“不声称写实相似”来绕过 `recognizable` 的身份硬门。

结果记录：`身份层：PASS / FAIL`，并列出改变身份判断的证据。

## 2. 风格语法层

从 `references/style-registry.json` 找到选中风格，完整读取其定义并逐项执行：

- 转换策略是否正确，是否退化为滤镜、去色、描边或材质覆盖。
- 比例、脸部语法、形状系统、线条层级、媒介、上色边缘和背景是否同时成立。
- 风格定义中的生成后硬门是否全部通过。
- 主参考的设计功能是否迁移，示例人物的具体内容是否被隔离。
- `reference_maturity` 之外的新结构是否只作为单张验证候选处理。

结果记录：`风格硬门：PASS / FAIL`。任一硬门失败，候选直接拒绝。

## 3. 当前任务层

- 基础人物：是否为清楚、中性、可继续扩展的正面母图；正式眼型是否可见。
- 三视图：正侧背是否等高、同基线、同一比例、服装结构和配色；正面是否已经确认。
- 表情或动作：是否只改变本次变量，没有改变人物与风格基准。
- 修复：用户指出的问题是否实际消失，未授权区域是否保持不变。
- 新增风格：是否与已有身份连续，且没有被当成正式风格提前写入角色包。

结果记录：`任务层：PASS / FAIL`。

## 4. 运行契约

若注册表的 `run_validator` 非空：

1. `run-contract.json` 中每个正向锚点必须有可审查状态。
2. 契约包含身份锚点时，身份锚点和 `identity_status` 必须与 `qa.md` 一致。
3. `qa.md` 的判断与契约状态一致。
4. 执行校验器 `--phase post`。
5. 身份或风格任一未全部通过时，契约状态只能是 `rejected`。

禁止把负面 QA 样本传入图片工具。负面样本只用于解释失败类别。

## 5. 交付判定

```text
人物身份层 PASS
AND 风格硬门 PASS
AND 当前任务层 PASS
AND 专属运行契约通过（若适用）
= 可展示为正式候选
```

每轮只能有一张当前阶段候选。失败后先交付根因和一个明确的下一步选择，不自动生成头像、脸部校准图或第二版。

失败图可以版本化保留在普通运行目录，但不得称为“可确认版本”，不得写入共享角色包。连续两次相同失败时返回上游重新分析，不继续堆 Prompt。

## QA 记录模板

```markdown
# QA

- 候选：<文件>
- 主风格参考：<文件>
- 身份参考：<文件列表>
- 身份层：PASS / FAIL — <证据>
- 风格硬门：PASS / FAIL — <证据>
- 任务层：PASS / FAIL — <证据>
- 运行契约：PASS / FAIL / N/A
- 最终状态：approved_candidate / rejected
- 下一步：<确认、修复或返回上游>
```
